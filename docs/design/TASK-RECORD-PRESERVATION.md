# 任务记录损坏保护评审

DEV-005、NFR-003、TST-007、AC-013。

## 故障和影响

固定 Harness 基线的逐记录 JSON 后端会跳过截断文档、无法读取的文档和不兼容的物理版本。对可重建缓存，这是既定语义。工作台任务保存用户交付、原生会话绑定及幂等回执，无法通过重放重建。底层跳过文档后，同一创建请求可以重新占用物理 key，覆盖故障文件。

## 暂定方案

在原生 JSON 后端增加由域声明选择的严格逐记录读取策略，供工作台任务域使用。逐记录表或全局槽的已有文件无法解析、版本不兼容或读取失败时拒绝打开该域。只有文件不存在才视为缺失。保留故障源文件，诊断提供域和文件位置，不记录文件内容。拒绝启动写入与工作台命令注册。标准 Harness 与无需保护的缓存领域继续使用既有读策略。

严格模式校验物理文档，不替代现有的业务 schema 校验。新建记录通过同目录临时文件、同步及拒绝覆盖的发布操作写入。这样在域启动后才出现的物理文件，也无法被创建重放覆盖。覆盖已知记录前重读其物理格式。继续使用独立 profile 和单写宿主管理更新。底层没有跨进程的比较后交换更新，部署时不得同时运行两个写入同一任务数据目录的宿主。

兼容现有逐记录 V1 和可识别的 V1 整域来源，不修改格式、任务 UUID、业务 schema、HTTP 接口或版本号。未知版本保持可诊断。备份和回退继续使用独立 profile 的完整备份和原来可读取的数据。发布前需评审上游策略，确定已发布且经验证的 Harness 提交。

## 备选方案

工作台直接检查目前 JSON 文件路径可以检测启动时损坏，但把物理布局泄露到应用层，而且无法原子拒绝写入期间到达的文件。路由到 SQLite 能避开逐记录 JSON 读策略，需要另做已有任务的跨后端迁移、故障文件保留和回滚。原生层按域启用策略可以沿用已有 profile 和数据，更新与维护由存储模块负责。

## 验收

以有效 V1 数据验证正常打开、幂等重放、竞争、备份和恢复。分别注入截断 JSON、不可读记录、不兼容物理版本及可读但错误的业务 schema，核对严格域拒绝打开、同请求重放不能写入、原文件字节一致。启动后在新任务 key 放入已有物理文件，确认排他发布不覆盖原文件。再确认普通逐记录域仍能跳过旧缓存，独立 profile 停用工作台后仍可恢复。验收命令与上线条件见 [测试计划](../../TEST_PLAN.md) 和 [部署说明](../DEPLOYMENT.md)。
