# M1 会话恢复与交付提交评审

状态为待评审。本文列出拟修改的契约和待验证的行为。通过评审后再更新 contracts/v1 及实现。

## 会话启动与恢复 · DEV-004

上游基线允许传入 sessionId。会话创建和工作区挂载分开，创建返回的 ID 也可能与请求不同。冒烟测试构造了与「创建完成、尚未挂载」相同的持久状态并重启 Host，验证盲重试原生 workspace create 会分配另一个会话。该测试通过 cwd-only 创建构造状态，未在原生 attach 调用中注入故障。

1. 应用服务先校验用户、工作区权限、现有运行与 revision。生成高熵 reservedSessionId，与 taskId、workspaceId、runId、intentId、请求摘要、已批准的 preset 和期望目录一起原子保存。通过可信原生查询确认该 ID 未被占用，再做一次 revision 检查。查询错误与确认为空分开。
2. 调用原生会话创建一次。正常返回需核查 returnedSessionId 等于 reservedSessionId，以及工作区成员关系、根会话类型、路径、preset 与其他任务绑定。满足后一次提交 Run 绑定和任务状态，再允许发送首条任务消息。ID 被替换或结构不匹配时保留已知候选，仅供待核对，禁止向候选发消息。
3. 超时、进程重启、attach 失败后，从应用记录读取未决 intent，借助宿主非激活查询读取该 ID 的 header、创建来源及工作区成员关系。还需要可信证据把候选会话确切关联到这个 intent。预留 ID、路径匹配和 preset 只是筛选条件。DEV-004 必须验证当前宿主是否能提供足够的关联证据；如果没有，进入待核对。用户可以在有权限时复核并选择符合边界的会话，或结束 intent。
4. 候选已存在但尚未挂载时，只考虑对核验过的原会话执行受宿主约束的单独挂载。验证 origin、目录、重复归属及权限后才调用 attach。挂载后再次读取成员关系，并按 intentId 与 revision 写入任务。若无法调用受支持的 attach 接口、证据不足，或挂载有冲突，保持待核对。禁止通过重复 session/create 修复。
5. 对确认不存在的预留 ID，只有在可证明先前请求已终止且无法延迟成功时才可发起新的用户授权尝试；其他情况保留待核对。已确认挂载但未写业务绑定的恢复执行相同步骤，不重复创建或发送消息。

拟补公共契约的 Run/状态投影为 reservedSessionId、确认后的 rootSessionId、意图及可展示的待核对原因。可信关联事实和内部对账信息保留在宿主存储层。reconcile 需要记录操作者、依据、结果及旧 intent；自动和人工决定使用相同的归属检查。

## 从 present 到提交 · DEV-007

模型从当前 Run 发起提交，宿主用调用侧会话推导 Run，查询该 Run 内已完成且可访问的原生 `deliverables/presented` 事件。事件只证明声明了路径，文件版本由宿主在提交时核验和计算。

| 模型输入 | 宿主选择 |
| --- | --- |
| `{ selection: "latest-presentation" }` | 当前调用会话中，当前 Run 边界之后、提交之前，最近一次成功 present 的全部文件 |
| `{ selection: "files", paths: ["brief.md"] }` | 以当前会话工作目录解析、校验后，从当前 Run 已成功 present 的记录选中指定文件；每个文件使用其最后一次匹配事件 |

每次进入阶段时，宿主记录当前 Run 的会话游标作为阶段起点，用事件序列划定选择范围。默认不跨会话消费展示事件。并列或有歧义的路径、空结果、超出权限、非当前 Run 或阶段的产物均拒绝提交。指定历史展示时由宿主返回可读的展示清单，再由用户选择；模型不拼接事件序号、Artifact ID 或 Evidence ID。

宿主以 sessionId、eventSeq、fileIndex 记录来源，以真实路径权限及大小限制读取同一文件句柄、计算摘要并核查替换，失败时保留原状态。对于可证的机器检查，从当前 Run 的允许事件或工具结果生成 Evidence，并按 criterion 关联。普通模型文本只产生 model-claim，缺少可信来源标记未验证。一次提交保存阶段、验收条件快照、选中的展示和产物版本。重复请求返回原提交，文件内容改变不会改旧记录。用户接受时重新验证提交版本。检测到漂移，返回 ARTIFACT_DRIFT，保留旧提交供比较；退回后再次 present 和提交，生成新版本。

拟修改 `agent.submit` 的公开输入为上述选择结构，保留受限确认结果。用户入口仍由服务解析受权限约束的已列出对象，区分可信展示与人工登记。公共契约变更、权限测试及调用方同步在评审通过后一起提交。

## M1 首条集成验收 · DEV-012

现有精简入口或认证 API 可作为测试操作面。使用真实 Harness Web Host、临时 storage domain、可控模拟模型、至少两次进程启动。以下每一步都检查持久状态和外部副作用。

| 步骤 | 操作及断言 |
| --- | --- |
| 1 | 注册工作区，创建任务和验收条件。记录阶段 ID，Agent 建议直接执行，用户改选先查证，阶段历史保留两条选择和来源 |
| 2 | 保存意图及预留 ID，创建根会话。注入会话创建后且 attach 前的故障，重启验证候选存在但未挂载，未重复调 create、未发送任务 |
| 3 | 对不足以自动关联的候选进入待核对。用已验证的原会话完成授权挂载并提交绑定。若适配能力不足，验收失败并报告所缺接口 |
| 4 | 模拟模型两次 present，第一次包含另一个文件。按 latest 或 paths 提交，核对只选择指定事件和文件、保存摘要和阶段，证据由 Host 生成 |
| 5 | 重启，同一任务、Run、阶段、提交和摘要可读，替换一个已提交文件，接受返回 ARTIFACT_DRIFT |
| 6 | 用户退回，保留原因与旧版本。原会话重交新展示、验证及新版本，用户接受。重启后查终态、两版提交及选择变更历史 |

阶段 ID 在同一任务内稳定。改变执行方式追加 revision、阶段 ID、来源、时间和可读依据。用户覆盖作为独立记录，旧提交绑定当时已确认的阶段。发布前补一条真实授权任务验证实际模型选择。

通过这条集成验收后才开始完整 Web 界面、扩展模板和列表性能。当前只有 M0 集成与上游恢复风险试验可运行，M1 工作台服务链路需要领域、存储、宿主适配与交付模块实现。
