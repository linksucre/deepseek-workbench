# M1 固定产物检查

DEV-007、FR-005、AC-005、TST-004。此设计供候选分支评审。

部署者按规范化的绝对工作区路径、任务标题、criterion ID 及原文、工作区相对产物路径配置规则。提交的验收条件和所选产物必须精确匹配。条件未配置时继续人工确认。已匹配的规则要求提交包含指定产物，否则拒绝提交，由用户或 Agent 调整展示选择。条件原文变化会解除旧规则的适用性。首批固定检查包括非空文件及不超过 1 MiB 的合法 UTF-8 JSON。

宿主先依据当前 Run 的可信展示解析产物。检查重新打开已授权的文件句柄，检查输入与记录的 SHA-256 在同一次稳定读取中验证。版本与提交候选不一致时拒绝提交。检查结果继承真实产物引用，和提交版本同时保存。任何失败都需要退回重交。通过的机器结果可满足该条条件，用户仍须确认其余条件并主动接受。旧提交继续保留历史结果，接受时仍重读文件哈希检查漂移。

检查由发布包中的固定函数执行。配置只从用户指定的本地文件加载。现有 owner 命令和模型工具输入保持原形状，模型无法提供检查结果或匹配规则。检查无需执行工作区脚本、通过网络读取数据或调用模型。

备选方案是从任意终端日志采信退出码。退出码与当前交付文件哈希之间无可靠关联，正文也可能来自工具的普通输出。后续如果接入项目 CI，需由可信生产者提交包含工作区、检查身份及文件版本的回执。当前固定检查的回退只需移除部署配置，已保存的审阅证据随提交保留。
