# M1 真实任务试跑

本手册对应 TST-005、AC-003 和 AC-007。试跑用于验证真实模型如何选择执行方式，以及用户能否通过工作台完成交付和验收。候选的模拟模型结果单独记在 [测试计划](../../TEST_PLAN.md) 对应场景中。

按 [本地部署手册](../DEPLOYMENT.md) 启动独立 profile，记录工作台提交、Harness 提交、Node 版本及模型标识。由任务所有者确认允许使用的工作区、资料、提供方和模型。用试跑专用目录保存产物。在每项任务的目标里写清约束、交付和成功条件，让 Agent 自行提出初始做法。

| 任务模板 | 可用任务 | 核对内容 |
| --- | --- | --- |
| 代码开发 | 给有测试的本地小工具补一个明确缺失的参数校验。 | 建议直接执行，编辑限定范围内的文件，展示修改和测试结果。用户退回一次，检查原会话能继续并提交新版本，再验收。 |
| 设计 | 为一个活动页制作页面方案，先由用户选择信息组织方向。 | 方向确认前先提交可评审草案。记录用户的中途调整及其依据，最终稿能追溯到所选方向。 |
| 创作 | 用已批准且当前环境可用的写作技能，根据本地素材生成一份可编辑说明。 | 建议复用技能，记录技能引用和依据，交付符合受众要求。用户在过程中覆盖执行方式时，核对覆盖的来源、理由和阶段历史。 |
| 调研与材料 | 根据两份有日期且含一项冲突的授权资料制作对比材料。 | 先核对冲突，产物注明来源和未确认项。通过工作台提交、退回、跳回原会话、重交并验收。重启后复核历史和当前版本。 |

每项记录实际建议、依据、用户覆盖前后的变化、阶段、会话是否复用、交付与验收决定。可组合多种做法，按实际时序和约束判断是否适合任务。把任务状态、产物版本、测试结果或必要的界面截图作为脱敏证据，保留人工复核耗时及可取得的用量覆盖和估算。记录失败和缺项，凭据、临时登录链接和未经授权的材料正文留在本机。全部场景有实测证据后，将结论回填 [验收表](../../ACCEPTANCE.md)。
