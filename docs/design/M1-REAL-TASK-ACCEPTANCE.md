# M1 真实任务试跑

本手册对应 TST-005、AC-003 和 AC-007。试跑用于验证真实模型如何选择执行方式，以及用户能否通过工作台完成交付和验收。候选的模拟模型结果单独记在 [测试计划](../../TEST_PLAN.md) 对应场景中。

按 [本地部署手册](../DEPLOYMENT.md) 启动独立 profile，记录工作台提交、Harness 提交、Node 版本及模型标识。由任务所有者确认允许使用的工作区、资料、提供方和模型。用试跑专用目录保存产物。在每项任务的目标里写清约束、交付和成功条件，让 Agent 自行提出初始做法。

| 任务模板 | 可用任务 | 核对内容 |
| --- | --- | --- |
| 代码开发 | 给有测试的本地小工具补一个明确缺失的参数校验。 | 建议直接执行，编辑限定范围内的文件，展示修改和测试结果。用户退回一次，检查原会话能继续并提交新版本，再验收。 |
| 设计 | 为一个活动页制作页面方案，先由用户选择信息组织方向。 | 方向确认前先提交可评审草案。记录用户的中途调整及其依据，最终稿能追溯到所选方向。 |
| 创作 | 用已批准且当前环境可用的写作技能，根据本地素材生成一份可编辑说明。 | 建议复用技能，记录技能引用和依据，交付符合受众要求。用户在过程中覆盖执行方式时，核对覆盖的来源、理由和阶段历史。 |
| 调研与材料 | 根据两份有日期且含一项冲突的授权资料制作对比材料。 | 先核对冲突，产物注明来源和未确认项。通过工作台提交、退回、跳回原会话、重交并验收。重启后复核历史和当前版本。 |

每项记录实际建议、依据、用户覆盖前后的变化、阶段、会话是否复用、交付与验收决定。可组合多种做法，按实际时序和约束判断是否适合任务。把任务状态、产物版本、测试结果或必要的界面截图作为脱敏证据，保留人工复核耗时及可取得的用量覆盖和估算。记录失败和缺项，凭据、临时登录链接和未经授权的材料正文留在本机。全部场景有实测证据后，将结论回填 [验收表](../../ACCEPTANCE.md)。

## 可复用本地场景

以下合成材料可用于准备并复跑同一组任务。接受真实模型试跑前，先由任务所有者确认试跑工作区、模型、费用范围和可用技能。需要使用业务资料时，可用获得授权的同类输入替换材料，保留对应验收条件。

从仓库根目录复制材料，把输出的目录作为临时工作区。每项任务使用对应子目录，产物也写在该子目录内。代码基线用 Node 自带测试运行器检查，可以在授权模型前完成。

```sh
trial_workspace=$(mktemp -d)
cp -R tests/integration/fixtures/tst-005/. "$trial_workspace/"
node --test "$trial_workspace/development/format-duration.test.mjs"
printf '%s\n' "$trial_workspace"
```

| 场景 | 任务输入与交付 | 人工核对 |
| --- | --- | --- |
| 开发 | 使用 [时长格式化工具](../../tests/integration/fixtures/tst-005/development/format-duration.mjs) 和 [基线测试](../../tests/integration/fixtures/tst-005/development/format-duration.test.mjs)。为秒数参数补校验，只接收非负安全整数，非法值抛 `TypeError`。提交实现和测试，保留原有 `M:SS` 格式。 | 核对 `0`、`60` 和原有用例。检查新增用例覆盖负数、小数、字符串、`NaN` 和超出安全整数范围。首次退回可指定补测一个漏掉的非法输入，等待同会话的新提交再复验。 |
| 设计 | 使用 [修理市集简报](../../tests/integration/fixtures/tst-005/design/event-brief.md)。交付两种信息安排供选择，再产出选定方向的手机及桌面页面预览。 | 保留一个方向草案版本和用户选择的记录，核对方向确认前后交付是否分阶段。最终预览主行动符合选择，两类受众都能找到自己的入口。 |
| 创作 | 使用 [纸样借阅素材](../../tests/integration/fixtures/tst-005/writing/service-notes.md)。交付可编辑的首次借阅说明。开场前检查试跑会话中至少有一项已获授权且适合短说明的写作技能。 | 记录引用的实际技能 ID。用户中途可改为直接完成或加入其他做法，核对阶段中的建议与用户覆盖都可追溯。终稿包含件数、借期、归还步骤和闭馆规则，待定信息保留为待定。 |
| 材料 | 使用 [筹备记录](../../tests/integration/fixtures/tst-005/materials/planning-note.md) 和 [场地方确认](../../tests/integration/fixtures/tst-005/materials/venue-confirmation.md)。交付一份带来源的活动安排，列出已确认和待确认项。 | 核对采用 24 名、东门、14:00，说明 28 名来自较早的暂定记录，并标出器材到场时间待确认。退回后把一处来源说明交给原会话修订，重启后核对两次提交和当前验收决定。 |

每项试跑至少留下任务 ID、提交版本、初始建议及依据、用户改选或退回记录、最终验收结论。计量使用模型用量投影和实际人工复核时长。准备材料和代码基线测试是本地准备证据，真实模型的实际选择和交付结果在获授权后另记。
