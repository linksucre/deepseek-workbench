# Web 工作台

归属 FR-007、NFR-004。经宿主 UI 插槽或允许的扩展入口装载，先通过兼容试验确认挂载方式。通过公共契约渲染任务列表、详情、验收和待核对状态，四类工作模板在任务创建时做提示，研究可加入材料流程。

交互包括加载、空、异常、权限拒绝、版本冲突、恢复确认、接受或退回。重复点击使用相同 requestId，版本冲突刷新后由用户确认。回归检查键盘操作、长内容、错误反馈和 50 条分页目标。

## 本地界面

[host-page.mjs](host-page.mjs) 在真实 Web Host 上提供 owner 受保护的同源页面和静态资源，使用严格 CSP。页面采用任务账簿与详情双栏，小屏转单栏。无外部静态依赖；工作区从宿主读取或调用原生 API 录入。任务列表按工作区分页，首屏最多 50 项，标题、交付路径和理由均以文本节点渲染。

[ui.mjs](ui.mjs) 实现四类任务模板、建改任务、就绪、启动、待核对、选择执行方式、提交、已提交版本及逐项验收。失败后的相同输入复用请求 ID，revision 冲突时刷新详情。任务操作区的「查看执行会话」将键盘焦点移到已绑定的根会话；会话区展示原生对话，并可发消息、暂停及恢复。Harness 原生交互，如工具审批或文件预览，使用原生入口及显示的会话 ID。

切换工作区时立即清空原工作区的列表、分页和详情。进行中的请求结束后加载最后选中的工作区，过期响应不再更新任务视图。读取失败时可在当前工作区重试。Chromium 延迟真实 Host 的列表响应，验证快速连切后只显示最后选中的工作区及其任务。

浏览器在真实 Host 的工作区中创建 53 条任务，验证首屏 50 条。切换到单任务工作区并返回时均从首屏请求。使用键盘触发「加载更多」后按宿主顺序追加最后 3 条，检查列表完整、无重复、所选详情保留及分页按钮隐藏。

`tests/integration/host-delivery-smoke.mjs` 使用真实部署 overlay 和 Host 验证页面权限、资源、分页和既有 M1 链路。Chromium 中验证添加工作区、创建任务、置就绪、启动会话和小屏响应式。使用 `tests/integration/list-performance.mjs` 验证重开原生 JSON 后端之后，3000 条任务的应用分页性能。

[浏览器集成测试](../../tests/integration/browser-workbench.mjs) 通过实际 Web Host、原生工具和模拟模型覆盖代码与材料两条完整交付路径，用 Tab、Enter、Space 和 Escape 覆盖工作区录入、任务创建、会话跳转及逐项验收。另验证 8192 字符目标跨重启、按普通文本渲染、产物漂移反馈的状态区域及 390px 小屏布局。CI 从安装后的本地归档生成 overlay 并运行同一测试。

浏览器在 Host 已保存接受决定后截断首次 HTTP 响应。页面提示错误并保留勾选项，用户再次点击接受时发送同一请求 ID。重放只返回原决定，未增加任务、提交或 revision。测试通过 Host 重启后的读取核对持久状态。

浏览器检查四种模板预填的交付物和验收条件，以及设计与创作草稿自定义字段的重启复读。复用测试夹具注入原生挂载失败，通过待核对表单验证拒绝错误 ID、重启后挂载原会话，以及结束意图后显式启动新会话。两条恢复路径均核对实际会话 ID 和数量，无模型请求。

浏览器通过任务操作按钮暂停、恢复和取消复挂后的会话。暂停期间隐藏消息输入，恢复后继续使用原根会话。取消后列表和详情均显示终态，历史会话仍可查看。刷新和 Host 重启后复读终态。生命周期操作期间原生会话数量保持一致，模型无额外请求。


任务详情的 Token 与费用区域按需加载。空估算仍展示实报计数及缺报提示；只有可核验且币种一致的费用才与软预算比较。浏览器回归覆盖预算提醒与缺报。

独立审阅放在有原生会话的任务详情中。活动任务显示问题与选中材料输入，旧审阅可读取状态与摘要。审阅中断后用户可核对预留状态，并在完成后显式回送当前 Run。

当前及历史提交提供可用键盘展开的「验收证据」。按提交时的验收条件显示已有的机器检查、用户确认、模型自述及未验证记录。模型自述的结果标作报告，缺失来源的机器记录按未验证展示。时间、摘要和来源均按文本渲染。Chromium 用真实验收回执验证用户确认，并用契约夹具验证其他证据类型。
已通过机器检查的条件无需勾选。机器失败阻止接受并保留退回入口。浏览器从固定检查的真实提交验证正负结果、重新提交及冷启动复读。

资料折叠面板打开后才读取索引。条目显示来源和登记日期，点击后在下方预览，使用纯文本呈现本地正文，经校验的网页链接由用户主动打开。阶段交接使用已持久化的选择、提交与决定，可复制到其他工作流。执行方式沿用任务详情中的显示名称，Chromium 在用户改选后核对阶段交接和资料预览。编辑现有任务材料时保留已有位置的日期及会话引用。

执行方式表单支持按既有契约组合多项方法，并填写任务类型、改选理由和可选技能 ID。任务详情显示当前类型、方法、来源、依据及所选技能。「填入任务说明」将当前执行安排复制到草稿，由用户发送给绑定会话。Chromium 通过绑定会话内的模拟模型调用原生建议工具，验证界面预选、键盘改选、空白理由拒绝、组合草稿、退回后的改选与重启复读。

已有资料路径按原值匹配和回存。文件名两端的空格参与匹配，既有会话引用及无法用一行编辑的路径随任务保留。网址录入复用宿主的同一校验函数。

回送在同一标签页保留待确认的请求 ID、任务及原 revision。页面重新加载时提供「核对回送」，重发同一请求并读取既有结果。成功或收到明确状态拒绝后重新读取任务 revision。用户再次发送已明确拒绝的回送时使用新的请求 ID 和最新 revision。
