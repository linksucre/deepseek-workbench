# 用量与费用

归属 FR-008、NFR-006。消费原生 token-meter 投影与可证的结算事件，按稳定请求身份去重。多个作用域合并前验证归属，未绑定的会话列为覆盖缺口。费率依据提供方、模型与时间生效，未匹配费率时金额为空。

显示报告字段、估算币种和覆盖说明。缺报按未知计数；局部已知保留局部值。统计与任务更新需要能在禁用模型调用时重算。软预算仅作显示和提醒。

## 固定 Host 的数据源验证

运行 `node tests/integration/usage-host-smoke.mjs /path/to/built/deepseek-harness`。测试使用本地模拟响应覆盖正常用量、计数省略、显式零和带用量的提供方拒绝。前后两次 Host 进程读取相同的会话投影和原生历史，重启后的读操作未发起模型请求。提供方和模型可从 `request/context` 读取，正常结算来自 `assistant/message`，拒绝场景的已报告用量保存在 `assistant/attempt` 的最后一个 `usage` 流记录中。省略的缓存字段在结算中仍为空，显式报零则保留 `0`。`tokenUsage` 投影会把两种情况都聚合为零。固定版本的 DeepSeek Messages 适配器也会把缺失的输入和输出计数填为零，两种情况在该适配器的原生结算记录中无法区分。验证使用 Node `22.22.0`。 [测试入口](../../tests/integration/usage-host-smoke.mjs)

TST-006 实现应按会话和请求归集原生结算，使用投影对账。只有原生字段可证明已有报告时显示实报零。适配器丢失字段是否存在的信息时，标记覆盖缺口。取消结算、`llm/retry-started` 的重试边界以及子会话继承历史的去重仍需验证。原生模式下可能出现不在任务会话结算中的辅助模型调用，应独立对账。任务归属、费用估算和完整 TST-006 验收等待 DEV-006 的生产接入。
