# 应用服务

归属 FR-003、FR-006、FR-009、NFR-001。读取当前身份及资源归属，再处理幂等与乐观并发，调用聚合并返回结果。定义 Repository、SessionGateway、EvidenceProvider、Clock 等端口。应用服务负责动作编排与失败语义。

Agent 建议记录来源与依据，用户覆盖后优先保留用户选择。接受提交时查当前版本和证据，处理缺失与漂移并记录用户身份。外部动作先写意图，完成后写绑定，结果未知置待核对。上下文索引只记录范围、来源和日期，按需从宿主读取。

[task-service.mjs](task-service.mjs) 集成领域命令与原生任务仓库。创建 ID 按用户、工作区和请求 ID 确定。写操作先确认调用者和资源归属，检查已记录回执并核对 revision，再获取文件或事件证据。回执重放返回当时的结果，记录与聚合在同一存储更新内。受信调用者只由 Host 边界创建；Agent 仅可对当前根会话对应任务建议和提交，验收必须由用户发起。确认根会话后，按 Run 初始化阶段 ID 和宿主事件游标；执行选择与修订号随阶段追加到同一任务记录。

reserveStart 只持久化意图，将任务置为待核对。原生创建由会话适配层负责，并确保同一意图只发送一次。bindConfirmedRun 仅接受适配层已核对的回执，并在提交时再次校验 intentId、预留会话 ID、工作区、preset 和 revision。持久化不足以证明来源时，适配层保持待核对。

`node tests/integration/application-smoke.mjs /path/to/built-deepseek-harness` 使用原生 JSON 后端和真实本地文件验证启动意图恢复、角色隔离、用户覆盖、幂等提交、漂移、退回和接受。会话绑定和事件切片是测试输入。DEV-012 仍需用真实 Web Host 再验证，并补齐原生可信回执、生产加载、提交工具和完整状态流转。

[host-runtime.mjs](host-runtime.mjs) 在 loopback Web Host 上挂载同源、仅 owner 可用的命令试验入口。HTTP 只做传输，命令输入和输出由 v1 公共契约校验。现有功能为创建、读取、编辑、就绪、用户选择、启动和待核对处理。入口随试验 profile 显式加载，供 DEV-012 使用；最终传输与 UI 接入仍在评审范围。拒绝非 owner、跨源、非 JSON 或契约不匹配的请求；未认识的内部错误仅返回通用消息。

`host-delivery-smoke.mjs` 在同一真实 Web Host 上验证 owner 会话、无认证拒绝、跨源拒绝、契约拒绝、任务写入、重启读取及相同创建请求重放。测试通过工作台入口启动会话，模拟原生挂载失败，重启后重放启动并复挂原会话。同一链路已接入原生工作台工具和用户验收，作为 DEV-012 验收用例。

[host-start.mjs](host-start.mjs) 串行处理本 profile 中的会话预留和核对。预留落盘后查占用，再调用一次原生 create。正常结果或带明确来源的原生挂载失败回执与意图存于同一记录。复挂须由 owner 明确发起，复核工作区、根会话、目录、preset、无运行记录及唯一性。挂载后重新从原生读视图验证，并用原 intentId 与 revision 提交绑定。缺少可信回执、回执冲突或会话来源不足时保持待核对，不重试创建。丢弃意图仅结束业务意图，不移除原生会话。

真实 Host 用例还移除了原生挂载失败的回执，模拟应用未获知结果的窗口。重启后，仅有预留 ID 和原生会话存在时，重新发起启动不产生第二个会话，核对接口拒绝挂载该候选。正反两组故障都不触发模型。

[host-tools.mjs](host-tools.mjs) 将 suggest 和 submit 仅暴露给活动或等待验收的唯一绑定根会话，工具执行时再次查绑定。原生工具协议使用公共契约可显示的 Schema 子集，执行前后仍使用完整 v1 契约校验。工具在会话身份下提交，并使用原生 callId 去重。无任务绑定的会话看不到这两个工具。

[host-review.mjs](host-review.mjs) 从阶段和上一提交的游标确定原生展示范围，在经过 Host 鉴权的入口核验同一工作区的文件。当前可由 owner 显式确认条件；自动测试结果到验收条件的映射仍待接入。验收前再次读取旧提交所指版本。

[entry.mjs](entry.mjs) 由源码 overlay 挂载原生存储、验证器、认证任务接口和 UI。[source-overlay.mjs](../../scripts/source-overlay.mjs) 验证固定上游提交与构建模块存在后，生成只引用本机受控源码的配置。task.list 只读当前工作区；游标绑定该工作区的排序边界，按更新时间和任务 ID 分页。

[host-start.mjs](host-start.mjs) 将原生会话创建限制在 8 秒内等待回执。超时返回既有待核对错误，并保留已落盘的启动意图。固定 Host 的原生创建接口没有取消信号。同一进程中，原生操作结束前拒绝结束该任务意图，同时允许其他任务启动。迟到的返回值不会写成可信回执或自动绑定，冷启动也不会根据预留 ID 接管会话。 启动核对先读取既有 attach 或 discard 回执。同一已受理请求可以跨重启重放，改操作、根会话或预期 revision 返回 INVALID。两种历史回执均存在时，仍可原样重放各自的输入。

[host-conversation.mjs](host-conversation.mjs) 使用任务绑定确认后的原生会话。只读对话筛选显式用户文本与已组装的 Agent 文本。恢复直接验证原会话，无模型请求；暂停和取消调用 DEV-004 的被动停止验证，并在任务持久化前核对 revision。重复发送以原生输入记录检查原文并返回既有回执。

生产 task.usage 使用现有 owner 命令边界，先核对任务读权限，再由用量模块核验每个原生会话的归属。可选本地费率和软预算配置在 profile 挂载时校验。读取不会更新任务或发起模型请求。

源码入口在任务服务加载前安装独立审阅预设的 Host 工具隔离，见 [Harness 设计](../harness/DESIGN.md)。

[host-delegation.mjs](host-delegation.mjs) 在共享会话命令队列中完成 owner 派发授权及预留，再调用原生隔离适配器。派发完成或用户明确核对时，以根会话目录及子会话头核验绑定，用第一轮原生结束事件和正文落盘。同一请求及重启后的核对均读取已保留状态。用户明确选择回送时才排入主会话。

## 资料索引与阶段交接 · DEV-010

[`createTaskContext`](task-context.mjs) 从已持久化的任务材料和正式提交的产物来源生成资料索引，同一来源、位置和观测日期只列一次，保留其引用来自 brief、提交或二者。每条记录带工作区和原始 `SourceRef`，索引读取不打开正文。模型自述及未提交产物不会生成资料条目。默认用 30 天标记资料过期，可由宿主配置。未来或无法解析的观测日期标记为未知。

按需读取首先核对选择引用是否与任务中记录的来源、位置和日期完全一致，然后委托宿主 `readSource`。读取前后均检查该来源的权限，返回前再核对任务工作区和 revision。宿主适配器需执行文件越界、URL 和会话事件的原生权限检查。返回的内容按来源数据处理。阶段交接使用持久化阶段和游标、当前执行选择、最近提交及对应的验收决定，可在原生存储重开后重新构建，无需复制资料正文或调用模型。

[`createHostTaskContext`](host-context.mjs) 使用现有本机 owner 身份、任务读权限、工作区注册表、原生文件服务和被动会话查询。文件在读取前后核对规范目标、工作区边界和原生版本，最多读取 64 KiB UTF-8 文本。链接只接受不含凭据的 HTTP(S) 地址并返回链接，不发起网络请求。会话引用要求任务绑定的根会话，仅打开显式用户或助手文本及已提交的原生呈现记录。呈现记录返回已保存的产物位置和版本。索引只检查文件元数据和候选会话绑定，实际文件解码与事件类型检查在用户选择后执行。

`node tests/integration/context-smoke.mjs /path/to/built/deepseek-harness` 使用原生 JSON 后端与原生本地文件服务，覆盖存储重开、文件和目录符号链接越界、内容上限和 UTF-8 校验。会话用例以确定性查询替身验证事件筛选、租约释放与解绑。Host 交付冒烟通过真实原生会话观察和文件服务，在重启后重新打开过期材料和已提交呈现。正式浏览器入口待公共操作评审。 [上下文用例](../../tests/integration/context-smoke.mjs) [Host 交付用例](../../tests/integration/host-delivery-smoke.mjs)

### Workbench 接入提案

为 FR-009 增加两个沿用本机 owner 认证的只读操作。索引操作接收任务 ID，返回工作区、revision、授权来源和阶段交接。来源操作接收任务 ID 与既有 `SourceRef`，返回对应文件文本、链接、会话消息或呈现引用。索引和内容使用同一原始引用，工作台在资料面板中只按需请求正文，并把模型文字作为普通资料渲染。保留旧客户端的任务详情响应原形状，单次任务详情读取尺寸也保持稳定。

备选方案是将索引内嵌入既有任务详情。单独操作可以保持旧响应兼容，资料权限或读取异常仍允许使用任务详情。拟议变更不需要存储迁移。回滚时撤销新增命令和资料面板即可。验收覆盖旧任务冷读、过期来源、外部任务拒绝、读取期间撤权、提交引用和浏览器重开。联调候选已接入 owner 读取及客户端，公共契约继续按工程流程评审。 [工程流程](../../docs/ENGINEERING.md)

交付装配可从本机 profile 载入固定产物检查。owner 命令和已绑定模型工具都经过同一交付适配器。机器结果由宿主注入，原有请求体和操作回执规则保持兼容。见 [M1 固定产物检查](../../docs/design/M1-MACHINE-EVIDENCE.md)。

[工作台资料设计](../../docs/design/M2-WORKBENCH-CONTEXT.md) 的生产入口通过 `task.context.index` 取得元数据和交接视图，通过 `task.context.load` 读取所选来源。两者只挂载在已认证的 owner 端点。资料读取复查任务版本及源权限，使用 Host 的实际工作区和原生文件能力。

资料预览保留文件开头的 UTF-8 BOM 和正文换行。宿主与表单使用同一网址校验。只读命令可从已持久化的引用回读真实用户及助手消息，工具结果仍拒绝返回。资料消息预览、任务对话和新结算的审阅摘要按 Unicode 字符计数，文本块之间的换行计入 8192 字符上限。已有的审阅摘要和普通消息回执继续按原记录重放。

独立审阅在预留之前校验已授权根会话和原生活动实例。相同派发请求重放先读已有回执。显式核对把原始输入摘要、审阅结论与任务 revision 同步写入，原生自动结算沿用独立回执。回送先保存请求及目标，再以独立的原生请求 ID 排队。先核对同 ID 回执。同一 Run 和审阅仍有未决回送时，新 ID 在写入前返回 `REVISION_CONFLICT`，结算后可另发。原生受理或明确拒绝入队后保存第二个 revision。明确拒绝要求原生结构化错误 `session/not-found` 指向本次目标会话。旧会话的兼容查询只查切换前的日志。新旧回送核对都要求可信原生记录含一个完整且正文匹配的文本块。同输入的终态回执直接重放。 [审阅设计](../../docs/design/M3-BOUNDED-REVIEW.md)

退回使用已授权当前根会话的原生观察记录截止游标，并与退回决定、revision 和回执一起提交。重放读取原回执。退回后的按文件或最近展示提交都须使用更新的原生事件。旧记录仅消费原生时间晚于退回决定的展示。
