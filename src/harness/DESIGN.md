# Harness 适配

归属 FR-004、FR-010、NFR-002。封装 workspaceRegistry、sessionController、原生权限与会话事件。通过启动兼容检查验证服务可用性，功能不足时返回 UNSUPPORTED。模型工具根据调用会话推导 Task/Run ID。

先确认现有 API 是否能保存可回查的创建标识。无法证明前次启动结果时进入待核对，用户只可绑定经验证的会话或结束启动意图。分发委派需独立工单，明确子任务范围、预算与写入隔离。Teams 只管理委派工作，任务验收仍由应用层处理。

待评审的启动意图、预分配 ID 与重启后核验见 [M1 会话恢复与交付提交](../../docs/design/M1-RECOVERY-AND-SUBMISSION.md)。盲重试 session/create 可能产生新会话，恢复不得用创建接口代替挂载。

## 固定 Host 的兼容检查

验证基线为 `4b399c39a6d1479cd84ca591b4d7c88e24d38a96`，范围为 FR-004、NFR-002 和 AC-004、AC-012。

- `sessionQuery.observeSession` 可读取指定会话。Host 内的 `Workspace.attachSession` 可对已有 ID 单独挂载，校验持久化会话的实际工作目录。工作台仍需在调用前确认用户授权、根会话类型和意图归属。
- 标准 `session/create` 接收调用方指定的会话 ID，返回的 ID 仍可能不同。创建路径仅向会话元数据写入目录和 preset。`SessionHeaderMeta` 也没有意图字段。普通根会话先落盘会话头，再写入初始事件，故预加载事件或 setup 追加记录仍存在只有会话、没有标记的崩溃窗口。上游的 `appendPluginRecord` 属于实验性接口，要求会话完成创建宣告后才能追加，迁移时尽力保留。
- 在同一固定 Host 上保留的方案是将证据不足的候选置为待核对，不重复创建、不挂载候选、不发送首条任务消息。用户可结束意图。若要在该崩溃窗口自动挂载原会话，需要评审受支持且与创建一并持久化的来源标记，或等价的宿主回执。旧会话和回滚后的未决意图沿用待核对路径。来源标记和回执仍是待评审设计。

实测使用 Node `22.22.0` 与已构建的固定 Host。`npm run check` 通过 6 项测试及仓库门禁。`npm run test:smoke -- ../deepseek-harness-run-4b399c3` 通过，模拟了会话已创建、尚未挂载的持久化状态，重启后仍可读取原 ID，盲重试生成不同 ID。上游工作区、Agent 生命周期、插件记录及会话 Store 成员约束共 154 项测试通过。现有冒烟用例用仅传 `cwd` 的原生创建构造崩溃状态，未在真实 attach 调用中注入故障。指定 Node `24.22.3` 与工作台层的 TST-002、TST-003、TST-004、TST-012 完整验收待执行。
