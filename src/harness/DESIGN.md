# Harness 适配

归属 FR-004、FR-010、NFR-002。封装 workspaceRegistry、sessionController、原生权限与会话事件。通过启动兼容检查验证服务可用性，功能不足时返回 UNSUPPORTED。模型工具根据调用会话推导 Task/Run ID。

先确认现有 API 是否能保存可回查的创建标识。无法证明前次启动结果时进入待核对，用户只可绑定经验证的会话或结束启动意图。分发委派需独立工单，明确子任务范围、预算与写入隔离。Teams 只管理委派工作，任务验收仍由应用层处理。

待评审的启动意图、预分配 ID 与重启后核验见 [M1 会话恢复与交付提交](../../docs/design/M1-RECOVERY-AND-SUBMISSION.md)。盲重试 session/create 可能产生新会话，恢复不得用创建接口代替挂载。

## 固定 Host 的兼容检查

验证基线为 `4b399c39a6d1479cd84ca591b4d7c88e24d38a96`，范围为 FR-004、NFR-002 和 AC-004、AC-012。

- `sessionQuery.observeSession` 可读取指定会话。Host 内的 `Workspace.attachSession` 可对已有 ID 单独挂载，校验持久化会话的实际工作目录。工作台仍需在调用前确认用户授权、根会话类型和意图归属。
- 标准 `session/create` 接收调用方指定的会话 ID，返回的 ID 仍可能不同。创建路径仅向会话元数据写入目录和 preset。`SessionHeaderMeta` 也没有意图字段。普通根会话先落盘会话头，再写入初始事件，故预加载事件或 setup 追加记录仍存在只有会话、没有标记的崩溃窗口。上游的 `appendPluginRecord` 属于实验性接口，要求会话完成创建宣告后才能追加，迁移时尽力保留。
- 在同一固定 Host 上保留的方案是将证据不足的候选置为待核对，不重复创建、不挂载候选、不发送首条任务消息。用户可结束意图。若要在该崩溃窗口自动挂载原会话，需要评审受支持且与创建一并持久化的来源标记，或等价的宿主回执。旧会话和回滚后的未决意图沿用待核对路径。来源标记和回执仍是待评审设计。

实测使用 Node `22.22.0` 与已构建的固定 Host。`npm run check` 通过 6 项测试及仓库门禁。上游工作区、Agent 生命周期、插件记录及会话 Store 成员约束共 154 项测试通过。指定 Node `24.22.3` 与工作台层的 TST-002、TST-003、TST-004、TST-012 完整验收待执行。

### 挂载失败响应与恢复

`npm run test:smoke -- ../deepseek-harness-run-4b399c3` 在临时工作区、已认证的原生 Web Host 和本地模拟模型上执行。测试插件仅对预留会话 ID 在 `Workspace.attachSession` 持久化之前抛出一次异常。标准 `session/create` 返回 `session/workspace-attach-failed`，`details` 包含原会话 ID 和目标工作区 ID。重启后，`session/list` 仍可读到原会话，工作区成员列表未包含它，盲重试会分配新 ID。下一次重启后测试插件通过 Host 读取原会话，核对目录、preset、根会话类型和未启动执行，再将原会话挂载两次。测试检查会话总数、唯一成员关系和再次重启后的持久关系。插件的注入对象和原会话 ID 均来自测试环境。工作台的回执落盘与授权检查仍需独立验证。 [测试入口](../../tests/integration/harness-smoke.mjs)

提交设计评审时区分两种情况。收到并完整持久化了与本次启动意图绑定的受信 Host 回执，可以将其作为归属核对的输入。只有回执记载的原会话 ID 与预留 ID 一致，且用户授权、根会话类型、工作目录、preset 和已有任务绑定均通过复核时，才可考虑调用单独挂载。响应丢失、回执未落盘或字段不一致时保留待核对。进程在记录回执前崩溃的场景仍需覆盖，收到错误响应不能消除该窗口。

### 停止与继续

`session/cancel` 返回的 `accepted` 表示受理停止请求，并保留待处理输入。当前基线的冒烟测试让本地模拟模型保持首轮运行，排入一条后续输入，再取消并通过 `session/wait` 确认空闲。排队的输入仍保留；重复其 `requestId` 不会唤醒会话，提交一条新的明确继续消息才会让保留输入继续执行。执行结束、重启 Host 后再次重放旧 `requestId`，模型请求数保持不变。

DEV-004 的业务接入应在写入 `paused` 或 `cancelled` 前，确认当前绑定会话已经停止。超时、需要用户输入或无法读取状态时，应用层保留既有任务状态。继续使用同一会话，只有明确要发送继续消息时才生成新的原生请求 ID；同一次消息重试沿用原 ID。原生停止会保留用户的排队消息。以上试验覆盖原生会话行为，工作台入口的竞争和 revision 仍留给 TST-003 与 TST-012。
